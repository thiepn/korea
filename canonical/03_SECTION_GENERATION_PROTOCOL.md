# Section-Generation Protocol v1.0
## FINAL CANONICAL — LOCKED

This document governs later generation of the **10,000 Sections** in the ten Part-specific chats.

No Sections are generated in this source package.

# 1. Structural Invariants

- Every canonical Subchapter must yield exactly **10 Sections**.
- Section ID format: `Part.Chapter.Subchapter.Section`, e.g. `VI.4.3.6`.
- Every Section must later support exactly **10 terminal Subsections**, e.g. `VI.4.3.6.1`–`.10`.
- No hidden numbered hierarchy.
- No 8/9/11-child exceptions.
- Architecture before prose.

# 2. Required Qualities of a Ten-Section Set

The ten Sections must be:

- collectively complete;
- mutually distinct;
- proportionate to historical importance/evidence;
- non-duplicative with neighboring canonical units;
- broad enough for ten terminal Subsections each;
- substantive rather than filler.

# 3. Allowed Decomposition Modes

Use the mode appropriate to the parent:

1. chronological;
2. thematic;
3. institutional;
4. spatial/regional;
5. processual;
6. comparative;
7. evidence/historiographical;
8. biographical-network;
9. material-cultural;
10. hybrid.

Do not force every parent into the same template.

# 4. Title Rules

Section titles must:

- identify substantive historical content;
- remain neutral toward disputed claims;
- be concise but scalable;
- use canonical terminology consistently;
- avoid generic labels such as `Background`, `Miscellaneous`, or `Other Issues`;
- avoid arbitrary `Part I / Part II` splits unless the historical division is itself meaningful.

# 5. No-Filler Rule

If a parent naturally yields only 8–9 strong Sections, do not invent weak units.

Instead:
- re-map the parent;
- combine over-fragmented units;
- split genuinely broad dimensions;
- use evidence/historiography, geography, social variation, consequences, or material systems only when historically justified.

# 6. Ownership and Overlap

Before drafting Sections, read:
- the parent Subchapter;
- Chapter owner rule;
- predecessor;
- successor;
- related cross-Chapter/cross-Part units.

A Section may not steal primary ownership from another locked Subchapter.

Developmental recurrence is allowed only when the question changes.

# 7. Evidence Rules

Every Section must have either:
- a plausible evidence base; or
- a legitimate source-critical/historiographical function.

Use the project epistemic categories:
- established evidence;
- probable reconstruction;
- disputed interpretation;
- traditional account;
- mythological account.

Thin evidence is not permission for speculation.

# 8. Cross-Cutting Checks

Where materially relevant, test for:
- environment/climate;
- health/medicine/disability;
- regional/local history;
- law/justice;
- everyday life;
- women/non-elites;
- migration;
- wider regional/global context;
- language/literacy;
- technology/material culture;
- memory/historiography.

# 9. Required Production Workflow

For every canonical Subchapter:

1. **Parent read**
2. **Internal map**
3. **Draft exactly 10**
4. **Internal overlap audit**
5. **Neighbor ownership audit**
6. **Private terminal-scalability audit**
7. **Coverage audit**
8. **Evidence audit**
9. **Correct/consolidate**
10. **Lock**

# 10. Scalability Gate

Before lock, privately verify at least ten plausible terminal topics beneath **each** proposed Section.

If this produces:
- repetitive micro-topics;
- artificial chronology slices;
- filler examples;
- duplicate terminal topics;

the Section design fails and must be repartitioned.

# 11. Part X Durability Rule

Contemporary Section architecture should remain useful after current events change.

Do not permanently allocate a Section merely to:
- the current officeholder;
- a short-lived policy;
- a single current trend;

when a broader durable structural category can own both current and future developments.

# 12. Locking and Versioning

Statuses:
- DRAFT
- AUDITED
- LOCKED

A locked Section title/scope may change only through explicit versioning and change-log entry.

IDs should remain stable whenever possible.
